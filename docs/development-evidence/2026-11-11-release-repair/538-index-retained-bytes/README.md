# Phase 538 — stop refusing the ledger index on retained bytes

A production account became unusable after the 2026-11-08 release. Both devices showed many-minute waits behind "Input is waiting to be saved.", and the desktop, which had never completed local reduction, took four to five minutes for each sent position. The operator reported it on 2026-11-11 and approved this repair the same day.

Phase 401 added a refusal to index eligibility: the retained graph (records, verified view and proofs) had to fit the existing 32 MiB ceiling. That ceiling was set on 2026-10-10 against raw record input. Phase 516 measured the retained graph at 25,969,753 bytes for 3,072 dense positions, so the comparison tightened the bound several-fold for accounts that existed before the release. Once refused, the owner drops only its semantic indexes and runs the full reference check on every later ledger change. The retained graph stays either way, so the refusal released nothing.

`accountLedgerIndexUsage` still measures and reports retained ownership but no longer refuses on it. The logical-row bound, the physical-row bound and the raw record byte bound are unchanged. It is one source line, kept to one line so no registered domain site moves. The test-only index build's anchor follows it.

Four existing cases that pinned the refusal are restated, and two are added: raw record bytes above 32 MiB still fall back, and an append stays incremental when retained proof bytes pass the old ceiling. Three of these fail on the released rule. Typecheck passes. On the finished tree the full unit suite passes with the CI command, `pnpm test --maxWorkers=1`: 335 files, 3,246 cases, one existing skip, 285.86 s. One earlier two-worker attempt on the same tree is retained as a failure: `test/inboundStaleTurnControl.test.ts` timed out at 5,009 ms against its 5,000 ms limit while the host's load average was about 14, then passed alone three times. No deadline was changed.

Bookkeeping follows [development.md](../../../development.md#release-bookkeeping). The ten CI contract checks pass. The planning inventory and manifest are re-recorded with all 1,105 obligations and 552 unresolved retained and none added; 178 adapter cases pass. The runtime census is refreshed after review: seven pinned sources had changed, six of them in phases 535 to 537 and one here. No changed line contains a domain label or cryptographic call and no registered site moved; `pnpm account:crypto-prep` passes. The census was clean at `e04879704` and `e9ec1e697`. `pnpm account:crypto-audit` now passes the census step and stops at 16 open constructions, the same count as on `origin/main`.

Limits. No browser suite ran, including `test/inbound-index/past-index.spec.ts`, whose fixture may need adjusting now that a refusal comes from the raw-byte check. Format and lint did not run from this worktree. Nothing was timed. The affected account's row and byte counts were not observed, so this repair is argued from the code and the lab's numbers and is not yet confirmed on that account. If its desktop is past the 32,768-row bound instead, this change does not help it. Reduction's starvation on busy or polling devices is separate work. No commit, push or deployment.
