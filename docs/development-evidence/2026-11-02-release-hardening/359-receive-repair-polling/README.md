# R1000: owner-local missed-hint repair — phase 359

The production receive owner now shortens its idle interval to 1,000 ms for 30 seconds after a verified quiet read discovers writing without a content hint since that publisher's previous verified read. Further such discoveries rearm the window. Hot backlog reads do not activate it. No local input, progress, transport result or unverified reply can manufacture that evidence. [Checks, faults and retained failures](./evidence.json).

This is per-slot scheduling state, not persisted trust. An opaque hint generation avoids counter overflow; publisher history is capped at 128, matching the existing quiet-hint bound. Read tokens are single use and carry the hint generation at request preparation, so a hint arriving during I/O cannot be absorbed at completion. Unnamed content hints conservatively concern every publisher. Successful hot reads update history but cannot arm repair. There is no separate timer: only the existing scheduler's successful idle interval changes. Failed operations keep their exponential retry clock, and integrity halts stay halted.

The first missing hint still waits for the ordinary idle read. Requiring a previous verified read is conservative; it cannot predict an unseen publisher's first missed hint. Healthy normal fallback remains 15–20 seconds and unhealthy fallback 5 seconds. The 750 ms retained-quiet eligibility, 5-second self checks, original selector and send yielding are unchanged. Self reads do not supply repair tokens. Authority adoption, retention install/cut, gate/login/reachability invalidation and owner close erase the state; clock rollback or a nonfinite clock does too. Close cannot be undone by a late completion.

They cover first discovery, rearming, normal hinted traffic, hints during I/O, hot drain, publisher identity/cap, token reuse, refused results, clocks, authority/owner reset and close. Scheduler integration checks post-drain timing, unchanged normal idle reads, original retry/halt behavior and maintenance's input/drain readiness. These are regression sensitivity checks, not app journeys or performance gate credit.
