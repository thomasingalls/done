# Phase 2 — preserve the actual device-preparation refusal

Depends on phase 1. The connection coordinator retains the exact startup kind/reason in a typed error and selects a corresponding user-facing message. Only unlock-required or creation-pending describes existing saved setup; migration, compatibility, removal, closed/missing identity, failed unlock, busy/unavailable/unsupported storage and cancellation retain their distinct requirements. A refusal neither writes a pending-device route nor generates replacement factor custody. Existing saved hints remain unchanged; fresh preparation still creates only its transient code and navigation hint.

Fifteen new presentation cases: fourteen fail against the former catch-all saved-attempt error, then all fifteen pass. Together with the eleven phase-1 and five preceding enrollment-state cases, 31 cases pass. Typecheck passes. These tests intentionally stub presentation inspection; they do not authenticate a synthetic disposition or establish native storage/lifecycle behavior.
