# Verified Local import selection preparation

This bounded L-1 phase follows pre-active import (`a0072e8`). The internal `selectLegacyImport` owner
selects that explicit Markdown/system destination through the existing Local startup, picker and admission
owners. It does not change default application startup, choose the author's real Stage 2 carrier, implement
fidelity restoration, delete source material or establish production old-writer exclusion.

## Handoff and authority

The host must exclude predecessor pages, workers, cached shells and transport throughout selection.
The disposable native harness establishes this externally and reestablishes it after each restart. There
is no public `excluded` boolean or callback. The owner is not exposed by a default application route.
An exact current origin/source observation must match the signed import binding before verification and
again before final custody commit. These observations detect change; they cannot prove quiescence, defeat
ABA or fence an old writer after the final read. Production cutover remains gated on an implemented
supported-version exclusion procedure. A new origin alone does not meet this same-origin source check.

The owner copies the input packet, authenticates the factor-bound import claim, derives the logical plan
from verified packet bytes and compares the complete source/policy/plan binding. Only `imported` and
`selecting` stages qualify. A new content owner authenticates current live custody, witnesses, counters
and every encrypted record. A new private Yjs document replays each consecutive slice receipt, refuses
pending dependencies, and verifies the full selected logical projection and system attribution. No caller
document, caller digest alone, or earlier `imported`/`selecting` claim substitutes for this cold verification.
Every resumed pre-active selection repeats it, even when the expected index row already exists.

Three native commits form the handoff under the existing exclusive slot lifecycle:

1. Advance the authenticated import claim from `imported` to `selecting` with exact previous-claim comparison.
   Its immutable initial custody, source/policy/plan binding and timestamp define the one selected identity.
2. Add the exact derived Local route to `done.slots`. An existing route must match; a closed, conflicting or
   malformed route refuses. The import marker still blocks ordinary startup/custody/index mutation.
3. Require the exact route to remain present in a fresh census, then in one custody transaction, compare the exact selecting claim, add the signed ready Local claim and
   delete the pre-active marker. **This transaction's completion is the active decision.** Its request success
   alone is insufficient. The Local claim retains authenticated import provenance and the selecting MAC.
   Its distinct payload domain authenticates both the provenance fields and their presence.

The final transition changes only ownership metadata. Live custody, store identity, generation keys,
content, counters and reservation history remain the same; selection neither appends nor reimports.
A crash after either earlier commit resumes from retained intent and rereads the destination. An aborted
final transaction retains the pre-active marker and has no ready Local claim. A completed final transaction
allows the normal factor-verified Local route and admitted initialization. There is no period when an index
row by itself authorizes the imported document.

Retries after the active decision authenticate the ready Local claim and input binding and check the exact
current route/custody/content census. They return the same selection receipt without comparing today's
edited document to the old import payload or recreating a missing index. This acknowledgement of an earlier
selection is distinct from a new content-recovery claim: ordinary open still authenticates and replays the
current content and journal. Source bytes are not required on this completed retry path, allowing later
cleanup to have its own progress. The input packet is still required for this preparatory retry API.

The existing Local clear owner explicitly refuses imported selections while source cleanup is unresolved.
Otherwise it could erase the destination and report a Local clear while recognizable legacy source remains.
Source cleanup and its integration with imported Local clear are a subsequent bounded phase.

## Tests and limits

`pnpm storage:legacy-selection` freezes production sources and fixtures, runs disposable native Chromium
cases and generated histories, and checks five named sensitivity controls. `--seed`, `--runs`, `--path`,
`--replay` and `--mutant` support reproduction. The external Node ledger supplies expected master/day/card
text. Generation varies source framing, Unicode, archives, day counts within the fixture's ten-day alphabet,
selection abort boundary and later edit. A separate damaged-content control shrinks and saves a failing
history; generic exceptions or timeouts do not count as control detection.

Native faults abort after request success at intent/index/decision and kill after observed transaction
completion at those boundaries. Commit-observation gates pause at the next crypto operation or fixture
return; they are not exact instruction cuts or an exhaustive crash matrix. Focused fake-IndexedDB tests
exercise malformed/authentication/refusal cases and generated partial states, not native exclusion.
Simultaneous selectors in one page use real Web Locks; no claim of a new multi-tab production exclusion
mechanism follows. Input/plan/replay memory and latency remain unbounded by the per-slice write budget
within existing packet/action refusal limits. Independent security/platform review and full product cutover
remain separate gates. Component evidence does not settle or pay whole-protocol obligations.
