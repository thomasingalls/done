## Phase A — precise bounded accounting

Keep the existing numeric session/process burst/refill ceilings, invalid-bearer allowance, body/page/deadline bounds and session-key attribution. One live HTTP request occupies one concurrency slot; sequential inner reads are not four simultaneous operations. Charge one admission unit before reading a bounded body. After exact batch framing, atomically reserve the remaining actual requested work before executing any inner read; a failed top-up spends the initial admission unit only and executes no subread. Refund only reserved subreads that never start (time/size cut or refusal); a started failed read remains charged and every request costs at least one unit. Failed/concurrent admission cannot consume partial additional reservations. A closed ticket cannot be enlarged/refunded; release/refund is idempotent or explicitly refuses misuse. Caller identities and request fields cannot select budget keys. Total live requests and per-request retained bytes retain existing ceilings; at most one inner read runs per request.

Choose evidence first: demonstrate max-four charging for one requested read, four-slot starvation of another same-session request, partial debit on a failed multi-unit reservation and charging unstarted tails. Add independent numeric/HTTP controls for exact counts, malformed input, exhausted/other sessions, refill/backward time, close/release, aggregate ceilings, native authentication and no partial responses. Preserve prior tests/assertions/deadlines, updating only the existing exact max-four expectation with an explicit full-batch companion. Close this phase and freeze its tree before load selection.

## Phase B — sustained-load attribution and policy decision

Units: a complete replay/load run is an observation; requests and entries within it are dependent. Separate API capacity probes from end-to-end browser observations. Synthetic micro/read stress is not user-visible replay. Target 1,024 sequential accepted positions, including a concurrent same-session interactive write and a second independent authenticated session sharing the same process budget. Use real signed requests/pages and compare independent oracle proofs, accepted prefixes, exact retry bytes, final writing and reopen where a browser is used. Record all failures and partial runs.

Measure wall time, response counts/statuses, capacity refusals, backoff durations, started native reads, request gaps, concurrent-write latency, process CPU usage and observed memory/RSS endpoints/peaks with sampling identified. Count query framing/signing outside HTTP separately. Browser primary: approval foreground elapsed; API primary: time for a fixed supported accepted-prefix workload. Compare ordinary frozen source with identical fixtures, three alternating pairs per selected owner/workload where feasible; retain all pairs and medians without population CIs. Use fresh and 96-edit fixtures as guardrails; a repeated single-position stress probe establishes admission behavior, not large-history cryptographic replay.

A demand/virtual-clock probe can prove policy-imposed bounds, but cannot establish real service capacity. Distinguish token delay from useful crypto/SQL work using explicit 429 and backoff timing. Initially retain numeric rates; select a changed policy only if ordinary measured native work, bounded memory/concurrency and concurrent writing support it. No global blanket increase justified by one idle account. Repeated measures are a fixed small engineering sample; no invented power claim. Stop/reconsider on incorrect evidence, starvation, unexplained >10% write-latency regression or increased failure/corruption. Null/mixed findings preserve existing numeric ceilings and select the next measured mechanism.
