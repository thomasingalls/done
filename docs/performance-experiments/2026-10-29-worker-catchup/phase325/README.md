## Three sender arms

|Arm|Behavior to compare|
|---|---|
|coordinated-2000|Existing 300 ms quiet / 2 s maximum local-flush and publication policy|
|reference|Existing reference build policy, frozen from the same candidate source|
|immediate-inflight|No artificial quiet delay: the first eligible edit starts a send turn promptly; later edits accumulated behind an active send leave together in its next eligible envelope|

The new arm is a lab prototype to be built only after the cold-stop prerequisite is resolved under separate direction. It must remove an artificial quiet wait at both publication and any coordinated prerequisite-flush scheduling, rather than leaving a hidden local quiet timer in front of an “immediate” publisher. It requests the required durability work promptly; it never treats a timer, unsaved edit or uncommitted state as permission to publish. Synchronous encrypted journal admission and input acknowledgment remain independent of networking. “Immediately” describes scheduling eligibility, not a promise of zero database, verification or transport time.

Keep one active publication turn per owner. No new quiet timer is armed to wait for additional keystrokes. Already sealed envelopes stay immutable, and edits that miss the sealed envelope are retained for the next turn. While the send/commit prelude is active, coalescing follows the existing ordered-source ownership rules, never speculative or uncommitted peer state. Pending writing is drained when eligible without requiring another edit to wake it. Actor/kind/epoch fences, byte/source bounds, nonce allocation, authority/signature/witness/chain/commit checks and all retry/backoff and lifecycle rules remain. If the accumulated writing exceeds the existing envelope bounds, it uses multiple bounded envelopes; “together” does not enlarge a limit. An offline/retrying send must not create a spin loop or let a new edit advance a retry deadline. This is a policy comparison, not a default selection or a flow-control hardening phase.
