# Persistent text buffers: boundary and review

The incremental runtime changes four files: workspacePreparation.ts, admissionQueue.ts, admittedWorkspace.ts and the pinned yjs.ts seam. Only private Local selection-snapshot composition uses reuse; reference preparation and Local handoff still make fresh histories, and Account capture retains its existing restrictions. Main runtime/tests/defaults remain unchanged. The selected comparator contains the earlier R3 and membership-repair work, not the parked publication or UI patches.

The preparation owner remembers known documents weakly. Fresh ownership is unchanged. Reacquisition additionally requires the exact retired state object, a live current preparing slot without an acquired state, and a live document. Registration occurs only during an adopted slot for an earlier transferred state, excluding that slot's current candidate. Alias wrappers, arbitrary same-shape states, foreign owners, duplicate retirements and current accepted state refuse. Retired registration is consumed once. A late callback fails the known-document check before destruction, even while that history is registered for reuse or belongs to a later slot. Borrowed-write cancellation still delays destruction and byte erasure until release.

Local acceptance may return the previous state. The queue registers that retirement only after canonical promotion, full comparison and workspace acceptance, before publication. The workspace owns any idle retired spare and destroys it on reset/close. This extends the trusted internal composition contract; arbitrary callback code is not sandboxed. The original no-reuse contract remains for callers that return nothing. The final implementation checks current-state identity through slot.prepared.state, whose existing cleanup clears the reference; it has no separate last-adopted strong reference.

The workspace retains at most one retired predecessor and a detached copy of the accepted update. The spare names the exact current accepted State as its basis. Only a text intent on a conservatively stable document can take it. Acquisition into the preparation happens before catch-up, so throws/cancellation use existing cleanup. Catch-up applies the previous accepted native delta, copies complete undo/redo ranges and owned selection metadata, and performs complete sameDocState comparison against the accepted basis before the next command. The incoming head's writer is then assigned as in fresh preparation. Native Yjs catch-up can transiently replace a retired document's writer on an apparent client collision; it does not change the canonical writer or bypass the final context/writer checks.

Every mutable stack item, range and outer metadata map is copied. Only the already owned opaque selection tokens can be shared. Source group capture, current selections, before/after metadata, redo invalidation and lastChange retain their existing behavior. Text-only transitions do not create redone links; those links are already present in the predecessor, and ordinary Yjs splitting preserves their offsets. Undo/redo or structural paths reset the spare and use the existing complete fork, including redone copying. Whole stack copying is deliberately retained, as is an additional full comparison on catch-up. No incremental-verification claim follows.

Actual afterTransaction changed types, not origin labels, decide whether a successful candidate can retire its predecessor. Existing master/card Y.Text is allowed; other roots, membership/map/array, metadata, archive, structural/unknown changes reject retirement. Remote delivery resets the spare and normalization fact before application, verification, publication or reentrant subscriber input. A failed or discarded candidate cannot become accepted or authorize a spare; retained write retries keep the same preparation. Each copied catch-up update is erased on consumption/reset. The existing queue erases its independent carrier/preparation buffers at their original lease boundary.

The normalization guard scans an unknown basis once, including deleted store content, keys, nested primitive values and pending state. It conservatively rejects any surrogate code unit, unsupported Yjs content, binary/exotic object data, cycles, sparse/extended arrays, nonenumerable fields and dangerous decoder keys. Ordinary text carries the result forward; structural/remote paths rescan. A surrogate insertion also uses a fresh fork. This first candidate deliberately forgoes reuse throughout emoji-bearing workspaces. It does not claim that every rejected shape actually changes under normalization. The negative-zero probe specifically confirms preservation, and the final guard allows it.

Tests demonstrate actual two-document alternation, erased consumed deltas, detached ranges/metadata, complete undo/redo, retained public values, admission pressure, same-candidate retry, discard, write-lease close and refusal on corrupted catch-up. Generated histories compare against fresh Local handoff with deletions, 1,001-character slices, selections, undo/redo, remote updates, metadata, no-ops, Unicode, retry/discard and cold replay. Existing tests add pending/remote/source/capture/selection/repair coverage. Three faults discriminate premature retirement, omitted replay and shared mutable history. Native browser receipts additionally require actual reuse on every ordinary measured key and zero reuse in the Unicode fallback condition.

This is a bounded runtime reuse experiment, not generic history synchronization. The caller must maintain exact predecessor and actual-text-transition invariants; matching encoded documents alone does not prove undo metadata or redone-link equivalence. New mutation paths must preserve these boundaries. Full stack copying, catch-up comparison, publication cloning, native update work and rendering remain. No heap/GC reclamation, long-session capacity, broad normalization domain, native multi-tab/Account qualification or release budget result is established by these controls.
