# F-17 persistent text-history buffers: first bounded experiment

Prospective protocol, 2026-09-15, above signed 85a58bd4. Comparator is R3 plus membership-repair eligibility, exactly the publication packet's selected.patch. Publication/UI candidates remain optional and excluded. Main runtime/tests/defaults are unchanged; all implementation and builds live in isolated scratch clones.

Question: can two alternating private Local text document/history buffers remove a document fork often enough to improve the common application screen while preserving accepted-state isolation and complete verification? The first increment retains full undo/redo stack copying. It is not the later incremental history or verification proposal, and does not claim O(edit) preparation. Persistent means owner-lifetime runtime reuse, not additional disk persistence.

The current one-transfer preparation owner must explicitly authorize retirement before reacquiring a previously transferred state. Retire only an earlier transferred state after another state is adopted. Never the current accepted state, foreign/new state, alias wrapper, reused retirement or live borrowed state. Old callbacks must still refuse before destroying an already known document, including after reownership. Default callers retain the old no-reuse contract. Queue adoption still performs its complete canonical comparison; retirement follows synchronous workspace acceptance and precedes publication. Workspace teardown owns any retired spare.

Only the private Local selection-snapshot variant may reuse. Retain at most one previous accepted history and a detached copy of its accepted text update. Before the next eligible text preparation, acquire that exact retired state into the new preparation, apply the saved native delta, copy complete undo/redo ranges and owned selection metadata from the accepted history, and compare the full document against the accepted basis before executing. Wipe the copied delta after use/reset. Keep all existing post-promotion verification, revision/job/slice/writer checks, borrowed-byte lifetimes, source capture and acknowledgement rules. No reuse for Account or generic metadata owners.

Retain only transitions whose actual changed types are existing master/card Y.Text. Remote, structural/unknown, metadata, undo/redo or invalid basis resets the spare. A conservative normalization guard scans an unknown basis once and caches its result along eligible text histories; it rejects surrogate-bearing fields/keys, unsupported content and pending structs/deletions. Text inserting surrogate code units falls back too. This deliberately leaves emoji-bearing workspaces on the fresh-fork path in this first prototype. The goal is correctness before extending normalization eligibility. The full reader, detached selection/publication API and mutation ordering remain.

Before timing, use directed and generated differential histories against fresh forks. Assert real document identity reuse, full document/visible projection/selection/history equivalence, native cold replay, normalization fallback, buffer and byte cleanup, undo/redo after text/deletion, grouped/sliced text, metadata/structural/remote resets, pending dependencies, refused writes/retry/discard/close and foreign/late ownership callbacks. Catch deliberate premature retirement, omitted catch-up, and shared history ranges or stale metadata. Preserve initial failures and repair before dependent timing. Use affected unit files, TypeScript and scoped formatting; no broad release suite per prototype.

Later blocks are not verified deep-history strata. No quantile subtraction, phone, forced-GC, memory or full-gate campaign.

Mixed evidence stays uncertain; consistent regressions support parking. Any unresolved correctness blocks selection and timing.
