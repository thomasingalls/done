# Adopted direction and corrections to the supplied perspective

The operator accepts prioritizing work that scales with workspace size and retained history. Existing constant-factor improvements remain selected; R4 indexing and publication reuse remain preserved options. The first phase is a growth diagnostic, followed by bounded repair/publication work, then persistent buffers with full verification, then incremental verification's separate proof and policy.

The perspective's scratch Node probes are reviewer-reported evidence; their source/results were not independently inspected or executed in this assessment. The original perspective is copied unchanged as perspective.md. Its SHA is pinned in start.json; the root original is left untouched.

Source/record checks at signed ac0b84ce support these corrections:

- The 47 ms exploratory median is a paint-proxy latency, not application-only CPU work. The 75 ms gate p95 has a different protocol. Subtracting older inclusive profile components from the post-optimization median does not establish 1–2 ms remaining CPU cost or a precise 9× requirement.
- Pinned Yjs Snapshot.js uses createDeleteSetFromStructStore; encoding.js also calls it when writing a state-vector delta. DeleteSet.js scans each client's structs. Small encoded output is not proof of O(edit) computation.
- workspaceCommands.ts returns from the text case before the final repairCardMemberships call. Text takes one pre-command repair pass. admittedWorkspace.ts queues a repair after remote delivery; skipping pre-repair solely on command kind needs an explicit repaired-basis invariant.
- A new immutable cards array invalidates a lookup memo on that array. React's useSyncExternalStore compares the returned snapshot by identity. Incremental publication needs selective observations with stable card/membership identities, not merely a new root-snapshot API. R4 retained full read/publication behavior and therefore does not settle that broader proposal.
- Pinned UndoManager's tracked changes clear redo state, merge or append stack items, update capture state and retain deleted items; the persistent-buffer transition must account for this behavior plus selection metadata, pending state, writer/group identity and slow-path undo/redo. Complete document bytes alone do not verify undo semantics. The existing preparation scope deliberately rejects reused history documents, so a long-lived-buffer design needs a revised ownership contract. Slow-path overlap prevents assuming unchanged peak memory.
- Transaction origin labels do not prove a write set or cover direct mutable-field changes. The pinned beforeTransaction hook fires before the transaction body's try/finally; throwing from it is not a general rollback mechanism. Incremental verification must define permitted old-state changes, normalized content/pending equivalence, detection delay and terminal failure. Keep full verification during the buffer prototype.
- A p95 difference is not a p95 overhead distribution and frame cadence does not cancel automatically. Preserve end-to-end measurements and describe their proxy boundary. The physical-device result remains historical context; no new phone campaign or conversion follows.
- Earlier component history scaling and deeper-history comparison do measure related growth. They do not qualify thousands of actual editor inputs in a full application session. This diagnostic adds an application-history contrast without claiming natural sustained typing, handset or fleet capacity.
