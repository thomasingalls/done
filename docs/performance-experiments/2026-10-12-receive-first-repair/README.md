# First receive repair: own polling and marker equality

Working-tree repair on signed measurement checkpoint `ee234d06521400e9d938b1874799e82f7fcac0e3`.
No deployment or receipt-format change; release validation remains paused.

## Implementation

- Keep the canonical promotion/joined marker payload as bytes and compare fresh authenticated
  payload bytes directly. The MAC payload, fresh custody/marker authentication, record comparison
  and commit fences are unchanged. Initialization, successor/membership installation and history
  custody refresh update the same owner-held expectation; disposal clears it.
- During productive catch-up with other publishers, skip an own-stream turn if it had a successful verified
  check within the existing five-second polling interval and verified delivery state contains no
  unresolved submission. First checks, expired checks and unresolved submissions still run.
  Once a peer returns empty, complete the ordinary sweep instead of duplicating that empty peer read.
- Do not infer resolution from the mere existence of an old response. A current-key retry retains
  earlier refusal responses; the verified current publication state and next submission decide
  eligibility. Read this scheduling hint with the prefix in the same fresh carrier load.
- Reset the poll hint on authority installation. Failed/rejected reads cannot refresh it; a backward
  clock change makes the next own check eligible. Single-publisher and receive-only owners retain
  their existing selection behavior. Four-page peer fairness and a sender turn after each page
  remain unchanged; this repair does not alter retry back-off.

The scheduling hint grants no authority and never advances a prefix. Each actual reply still receives
the existing authentication, source binding and durable admission checks. This is the prerequisite
repair identified by the [attribution packet](../2026-10-12-receive-attribution/README.md), not grouped
receipt processing or network prefetch.

The local final run takes **22.5% less time** than the fresh frozen baseline. That baseline is 6.4%
slower than the earlier 308.307-second observation, inside the predeclared 15% drift threshold. The
candidate is also 17.5% faster than that earlier observation. The final delayed run takes **19.4%
less time** than the prior packet's 374.759-second delayed baseline; that comparison lacks a fresh
delayed baseline and should be read accordingly. No extra repetitions were triggered by the stated
local-gain/drift rule. This is a bounded engineering comparison, not a population effect estimate.

The intermediate candidate had an unnecessary duplicate-empty-peer path during idle sweeps. The
final change retains ordinary idle sweeping and has a directed unit control. Its delayed burst
median is back near the earlier baseline's 2,385 ms. These short serial samples do not isolate the
idle correction's causal contribution from run variability, nor establish an across-device latency
guarantee. Bursts include publication batching and assertion polling. The extra local peer request
has a distinct cursor: the browser starts reading the concurrent writer's newer tail before the
completion assertion observes the original 600-position backlog. It is not a duplicate cursor.

All complete exports agree in both directions and after offline reopening: **54,211 bytes** in every
run. Writer activity and the receiver-side sentinel both arrive. No HTTP refusals or 429s occur in
the primary windows. Logs retain HTTP-200 abort flags/closed subscriptions and deliberate offline
setup failures; these are not described as zero-network-error runs.

Final local catch-up has no recorded long tasks over 50 ms; final delayed catch-up has one at
1,060 ms, versus one at 1,147 ms in the fresh local baseline. Isolated long tasks remain and were
not attributed to compaction or audits here. Final collected heaps are 19.57/19.58 MB, versus
20.90 MB in the repeated local baseline. They are endpoint observations, not peak-memory bounds.
Cold opening remains roughly seven seconds and beyond the 2.5-second budget; this is not a cold-open
repair. No current phone or production-cluster measurement follows from these local observations.

## Result and next step

The final source passes **16 focused unit checks**, **five focused native cases**, TypeScript,
targeted lint/format, ordinary build and whitespace checks. The preserved old fault-control failure
is separately explained above and reproduced on the baseline. Numeric archives reproduce their
summaries. The runtime patch and final source/bundle hashes bind the measured code.

Retain this incremental gain. Next group the owned processing of existing one-position receipts,
amortizing repeated authority checks and loads while keeping per-entry authentication and exact
durable readback. This phase neither implements that grouping nor changes retry back-off, custody
MAC encoding, local retention or checkpoint-admission policy. Both constituent optimizations were
measured together; there is no new isolated speedup attribution to either one.
