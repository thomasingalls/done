# Membership-repair eligibility: source review

The incremental runtime patch changes only workspaceCommands.ts and admittedWorkspace.ts. It adds a per-owner command-runner closure with a WeakSet of histories. runWorkspaceCommand remains the unconditional reference adapter; the new runner's private execute function accepts the already-established basis fact. No caller-supplied intent metadata, state-vector shortcut, generic transaction-origin classification or application-level capability authorizes skipping repair.

Every successful initialization/text/structural command completes the existing repair policy. Text actions only operate on the resolved Y.Text and editor selections, so they preserve that completed repair state. This is a fixed-point/policy claim, not a claim that every card has a live collection: intentionally retained unfiled/legacy-compacted cards remain supported. All non-text commands retain their existing pre/post repair calls, including undo/redo and repair itself. Throws clear that candidate's claim.

The only history forks used by the owner preserve the full document and existing ownership checks. Inheritance flows from the current accepted history to its detached candidate. Successful preparation records the candidate alone. Reference adoption and verified Local handoff already transfer that history identity; discard/teardown already dispose it. Weak entries do not retain discarded documents. Unknown/new owners begin without a claim. No new writer/revision/state ownership or disposal mechanism is introduced.

Every accepted non-local event clears the current history's claim before applyUpdate, consistency verification, emit and the existing queued-repair test. This covers text-only updates, pending-only updates and later dependency delivery. A subscriber's reentrant local input therefore cannot reuse the pre-receive claim. Conservatively scanning after every remote update is intentional; transactionAffectsMembership narrowing is separate.

Focused assertions verify exact scan counts on repeated/no-op text, retained non-text scans, dirty pre-command repair before editability, system/human transaction order and source-byte replay, late pending dependencies, failed storage/retry without rebuilding, discard without blessing the accepted basis, closed API refusal and separate owner closures. The generated differential compares full document state, command results, undo/redo depths and selections with the unconditional adapter through actual detached forks. Existing affected suites cover broader structural/selection/projection ownership behavior. Deliberately omitting invalidation or blessing the source from an unaccepted candidate fails four owner modes each.

The optimization relies on the existing sole-mutator owner boundary. Future document mutation paths must invalidate or establish this private fact; they must not infer it from update origins or a matching state vector. Account source tests here use the real admission owner with controlled carriers, not a native account integration campaign. Native ownership/memory/Account composition qualification and the unchanged application gate remain separate RC work. No additional verifier scan is removed.
