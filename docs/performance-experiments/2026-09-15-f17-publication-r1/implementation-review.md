# Incremental publication boundary

The incremental runtime adds workspacePublication.ts and wires it into admittedWorkspace.ts. The established full projection is moved into a shared function with the same card/day/header/archive fields and order. Only private local-snapshots mode instantiates the cache. Reference preparation and Local handoff call the full reader; Account capture retains its existing preparation restrictions. No Yjs codec, command behavior, source capture, document verification, public UI API or notification scheduling changes.

Preparation observes actual transaction.changed types after the history fork and removes its observer in finally. Existing master/card text is recognized by type and parent identity; card IDs must resolve back to the same card and text object. Structural, archive, metadata, detached/unknown or other changes require a full projection. Origin and command labels are irrelevant. Plans contain revision numbers, booleans and target strings, are weakly keyed by prepared state, and are consumed only by accepted Local adoption. They contain no old document/history/byte reference chains.

The cache holds one projected snapshot plus card/day indexes and sensitive-field sets. External reads always structured-clone it. Repeated reads at one accepted revision reuse derived work while returning fresh nested values. Advance accepts only a matching cached basis and nonstructural plan; absent/stale/full plans invalidate. Every remote delivery clears before application/publication. A dirty repair transaction triggers the full path even when its associated human edit is text. Verification remains ahead of exposure, and teardown drops both publication and archive caches.

History forks can normalize unedited fields without recording a transaction. Sensitive master/card/archive fields are therefore reread, and the header is reread from the new accepted document. Every surrogate code unit is sensitive, including valid pairs that may cross item boundaries. Shape keys/member IDs containing surrogates force the full path because their normalization can affect keys, collisions and ordering. Card metadata (author/origin/location) is included in sensitivity; actor/device/settings header metadata is always refreshed. Values are committed into private arrays only after all source reads succeed. The two live history counters are checked on read, including the existing out-of-band history-clear diagnostic.

This reduces repeated CRDT walking, stringification and projection construction; it does not make public cloning constant-time, eliminate React rendering, or establish a heap/GC improvement. Work still depends on the number of sensitive fields, header size and output size. A workspace with many sensitive archives/cards may gain less. New document mutation paths must preserve the owner and transaction-classification contract; standalone callers cannot forge a plan through the public workspace API.

Focused/module/generated/full-owner tests exercise normalization, aliasing, structural/remote fallback, stale and absent plans, actual source capture, pending dependencies, refusal/retry/discard, close, undo/redo, history clear and retained editor projection behavior. Three deliberate faults discriminate missing refresh, ignored structure and leaked mutable outputs. Native multi-tab/crash/Account composition, memory and the unchanged release gate remain promotion work. The controlled-carrier tests and six-session browser screen are bounded exploration evidence.
