# Experimental text-only publication reuse

Baseline: signed `20a535c44d2c33b394306fa67023c62d2d9c5f40`, explicit `local-snapshots` mode only.

Hypothesis: a card or Goals keystroke currently reconstructs every card body, location and day membership before publishing to React. Reusing the previous private projection when actual Yjs transactions changed only existing card text or master text should reduce that work. This does not avoid the React render itself.

Mechanism: preparation records changed text targets and the verified input revision. The accepted Local adoption refreshes only those strings and history counts when an existing cache has exactly that input revision. Any other changed type, any remote delivery, no cache, or revision mismatch falls back to the existing full reader. All reads return structured clones of the private snapshot. The cache stores only projected values, no Yjs objects, old histories, byte leases or capability tokens; teardown drops it. Notification timing and all admission, same-state, refusal, transport and history checks are unchanged.

Expected tradeoff: extra private projected data and a structured-clone output pass replace repeated Yjs walking/stringification and day/card membership parsing. This could lose on tiny workspaces or expensive output cloning. The shared browser screen, not source inspection, decides whether it is useful.

Focused correctness plan: existing workspace-admission cases plus one new case in each of the three preparation modes. The new case mutates every kind of returned nested projection, retains an older snapshot, and compares text, structural move/undo, settings, actor, remote/unknown-root and later text transitions to cold reference projections. Existing cases additionally cover refusal/discard, archive mutation and deletion, remote dependencies, generated undo/selection histories, close and reentrant publication.

Unqualified risks: the changed-type allowlist is derived from pinned Yjs transaction semantics; wider generated mixed structural/remote histories and native close/refusal fixtures remain promotion checks. Cached plaintext must remain scoped to an unlocked owner. Direct malformed internal prepared-state mutation is outside the private seam contract, but existing complete canonical-state verification still precedes exposure. The public/default modes remain unactivated.

Measurement results are owned by the root's common benchmark; this agent does not claim a measured speedup.

Focused evidence: direct installed Vitest ran `test/workspaceAdmission.test.ts`: 89/89 pass (6.28 seconds). Initial TypeScript pass caught type-narrowing errors and a readonly-property mutation in the new test; these were corrected with explicit checks/casts. Final direct TypeScript build passes, and the final 89-case test rerun also passes. The initial and final logs are retained. No full unit/native suite or release gate was run.

Review caught and reproduced a real defect before browser measurement: a cached lone-surrogate Goals value could become stale when the next history fork normalized it while only another card was edited. Reference and handoff passed the reproduction; the cache candidate failed. `normalization-repro.log` and `candidate-before-normalization-repair.patch` preserve that result. The repair makes a projection ineligible for reuse whenever any projected string key/value contains a UTF-16 surrogate code unit, conservatively including valid emoji pairs. Eligibility is scanned once per full read, then only changed strings on incremental transitions. This avoids assuming that a displayed pair is one encoded fragment and covers metadata such as actor/device names. Emoji-bearing snapshots therefore currently take the full reader on each accepted transition; this limits the candidate's reach and is not concealed as a general speedup. The extended test covers high/low lone surrogates, valid emoji, Goals, actor metadata and device labels across later forks. Final workspace suite: 92/92 pass; TypeScript passes.
