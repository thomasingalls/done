Decision: reduce the original device's Compare and approve waiting time without changing reader eligibility, typed-comparison/transcript authority, durable staging/read-back, expiry, concurrency, crypto predicates or interrupted/retry behavior. Deployed baseline is faf465f7; current signed a18d5d1c differs only in startup-refusal repairs and evidence. No production profile/data or deployment.

Primary outcome: elapsed time from original-device Compare and approve click to foreground operation completion. Secondary: time until both device certifications, time by local CPU versus authenticated HTTP endpoints, accepted-history read count, long tasks. Measurement unit is a full resumed disposable connection, not individual requests. Initially investigate 0 and 24 separately delivered Goals bursts, an existing joined approver, and an additional candidate. Use the established virtual-passkey browser convention, actual network-session/membership services and real storage/cryptography. A fixed 75ms delay on each history-read reply is a labeled diagnostic sensitivity condition, not a phone/WAN estimate.

First attribution run: create real writing and wait for each burst at the other device, so each requires a distinct accepted position. Profile the approver only between comparison and certification. Preserve request paths/status/elapsed only. Capture quiescent service/browser snapshots privately before the timed approval; all snapshots, codes and credentials stay outside Git. Later before/after runs must restore exact same snapshots, alternate order and retain all failures/deadlines. Use at least three matched pairs for directional latency evidence, report raw observations/ranges and avoid population/tail claims from small desktop samples. Target at least 20% primary reduction on the history case, no removed verification, unchanged export/writing and no consistent fresh-case regression. If timing is too noisy, use exact operation/request counts and report inconclusive speed magnitude.

Checks must reject malformed or missing evidence, wrong cuts/authority, cancellation/interruption and changed local records. Reopen both devices and verify writing and two-way sync. Security checks take precedence over speed. No extension of deadlines, server limits or bypass of factor/cryptographic validation. Existing tests and release blocks remain. Findings requiring a new trust/format contract need a separate bounded design before implementation.
