# Bounded transport batching contract, before implementation

Goal: reduce history replay round trips for device approval, retaining the one-position authenticated inbound verifier, source completeness and every crypto/authority predicate. No changes to enrollment decisions, durable progress, factors, schemas, authenticated request/page formats or reader eligibility.

New optional HTTP route: POST /account/delivery/read-v2-batch, workspace grant, binary framing containing 1–4 exact existing v2 signed read requests. New closed framing uses distinct request/page tags, uint32 count and uint32 lengths with exact trailing-byte exhaustion. Each request <=4 KiB; aggregate response page bodies <=10 MiB; 1–4 signed inner pages. The framing itself supplies no authority. Each returned page is paired by array position with its exact outstanding signed request and passed through the existing verifyInboundPage. Nonce/request binding, signatures, historical publisher/reader, epoch, generation, hash chain, through monotonicity, accepted cut, actor/Yjs/bounds and lifecycle checks stay unchanged.

Server executes inner reads sequentially in requested order through authority.readInbound and its existing transaction-time authorization. Thus through observations preserve the current sequential timing contract; no concurrent read snapshots are reordered. Reserve the existing request-budget units conservatively for all four possible reads, preserving per-identity/global inflight and rate limits rather than making batching a budget bypass. Keep the existing 10-second request deadline. A failure returns its existing refusal, with no successful pages exposed from an incomplete group. Response-size bound may return a strict nonempty prefix; the client verifies that prefix and creates fresh requests for the remaining positions. All intermediate read results are read-only.

Client prepares requests only through the authenticated publisher cut and existing 4,096 replay-event ceiling. Each signed inner request retains its 30-second expiry. New batching is used only by the additional-device snapshot replay initially; unrelated receivers/history consumers stay on their existing path. Hold one existing NetworkLogin owner callback for a group rather than introducing overlapping ownership. A 404 from an older server alone permits the original first request on the original route, returning one verified page; retain this unsupported hint only for the unlocked coordinator. Authorization, integrity, size, timeout and other failures do not authorize fallback or advancement. Untrusted hints can only choose the slower path.

Memory: aggregate inner page bodies <=existing 10 MiB page limit, plus small length framing and decoder copies. Do not permit four maximum-size pages or unbounded Promise fan-out. Erase captured requests/pages on failure and completion; drain work before owner disposal. Source documents/keys retain current cleanup and no new persistent cache is introduced.

Evidence before accepting: framing malformed/trailing/count/size controls; real scoped HTTP no-grant/wrong-scope/cross-account/revoked/malformed/subread authorization and request-budget controls; unchanged single-read tests; history-source equivalence and corruption/cancellation/cut refusals; browser enrollment at history depth, old-server fallback and lost reply. Compare exact restored fixture runs in alternating order, at least three pairs, with both working crypto and writing/export equivalence. Retain every failed attempt and report local/virtual-provider limitations. New tests gain no aggregate qualification credit without reviewed adapter ownership. No deployment.

## Review amendment before final acceptance

After observing the initial matched results, review identified that four individually slow reads could exhaust the unchanged whole-request deadline. Add a cooperative 250 ms completed-work bound: after a read completes beyond that bound, return the nonempty prefix without starting another read. It does not preempt ongoing cryptography or extend the ten-second deadline. A fake-clock regression must prove no second read starts after the bound; repeat final matched measurements with this guard.
