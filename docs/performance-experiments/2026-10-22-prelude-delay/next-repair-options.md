# Next-repair options, conditional on phase27 trace

This is a design note, not selected implementation or phase28 contract. No product source changes here.

If measured immutable authority/history verification dominates discovery/catalog, the smallest scope is discovery and catalog-read only. Bootstrap, source reads and checkpoint mutations retain their original full verifier. Both current consumers already separate complete mathematical history from fresh request authority and live ledger/census/final native guards. Reuse only the stable header projection proven in23/26, retain publisher and all native/future fields, and use the existing128-entry/16MiB/2MiB bounded core pool with fresh custody and input/revision/lifetime fences. Do not add another independently budgeted cache or broaden proof reuse to request/grant/session authority.

A complete proof must preserve `{authority, history}` for early epochs: merely adding `.history` to early delivery authority changes ledger dispatch. A private proof producer may carry complete branded history through the existing copyAuthority mechanism, then return early authority without that carrier history using the same canonical needsMembershipHistory branch that selects early/later authority. Later authority already uses the identical branded history. Compare full adapter outputs against the original producer across early/first-successor/certified/continued/rotated/recovered/removal fixtures, including private brands and independent no-pool results, so a future producer shape change fails loudly. No carrier reaches ordinary delivery consumers directly.

The current pool hashes context, then checks verifier identity; equal normalized read/publication and complete-history contexts with different verifier callbacks can evict each other. Possible remedies: (a) per-verifier identity namespace in the same bounded pool, with weak identity ownership and unchanged global entry/byte/LRU accounting; (b) generic verified-evidence envelope stored by that same pool. Prefer the least change consistent with proof-shape/ownership controls. Avoid injecting a purpose property that could overwrite a future native field, and avoid a second full cache budget. Identity is code/proof purpose, never a replacement for exact native context or pin.

Necessary evidence for a selected28 repair: real signed discovery/catalog requests spanning genuine writes, cold/warm proof work counts; ordinary read/publication coexistence without eviction; invalid requests, current grants/completion/expiry/custody, live witnesses/full census/served/cut checks, changed authority/pin/native/future fields and immutable boundaries, private brands/early dispatch/no-pool, clear/close/in-flight mutation/failure/oversize fallback, account/publisher separation, real four-attempt races and mutations/pruning not reusing. Existing tests/assertions/deadlines preserved; new cases should fail before repair. Omission controls for each moved dependency. Full original uninstrumented R26,C28,C28,R26 with fixed client110, fixture/rates/resource envelope and16ms/2500ms/30s/600s/120s/data gates; no selective rerun or threshold tuning. Separate attribution if failure remains.
