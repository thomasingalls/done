# F-17 exploration round 3 — profile selected combination, target one bottleneck

2026-09-15. Start from signed 602e4cee plus round two's selected preparation + comparison-pool + editor patch. No main runtime/test/default changes. No Rust migration, personal server, phone, relay or deployment work.

Decision: identify a substantial remaining cost in the actual selected application's edit path and determine whether one bounded change gives a useful incremental improvement while preserving semantic checks. Use a mechanism-oriented profile followed by an exploratory paired benchmark, not release qualification or a statistical population estimate.

First run two fresh diagnostic sessions of the selected variant on the same 20-day ×15-card /400-Goals-line corpus and explicit edited-card marker. Pinned Chromium 151, Pixel 7 settings, 1280×900 viewport, CPU4 after unthrottled UI setup. Use eight warmups then60 keys under CPU plus allocation sampling. Force GC only at the existing diagnostic boundaries. Retain source-mapped self/inclusive CPU, sampled allocation, heap before/after/lock, exact text and bounded undo/redo/cold-reopen checks. Inclusive stacks overlap; sampled bytes include collected objects and are not retained memory. Instrumentation perturbs execution and cannot establish a causal speedup. Two runs help distinguish persistent hotspots from one-session attribution, without a formal precision claim.

Before timing a changed candidate, record the observed target, mechanism, source boundary, focused semantic checks and remaining risks. Prepare at most one candidate. It may refine or compose an existing patch; keep source identity and negative results. Do not weaken detached ownership, complete-state comparison, staging, journal durability or recovery to save work. If no defensible candidate emerges, retain the findings and stop this bounded round.

For an eligible candidate, run focused affected tests and TypeScript, then four ordinary-text sessions selected/candidate/candidate/selected and one Unicode pair selected/candidate. Same packaged UI seed, CPU setting and corrected round-two helper:8 warmups,40 early measured keys,96 more warmups,40 later keys,50ms gaps. Explicitly assert marker and requested emoji presence. Exact text after each block, bounded undo/redo and cold reopen must pass. Record every sample, order, build identity and failure. Builds/tests and browser sessions are serial; no heavy parallel work. After correctness failure, preserve it and investigate before dependent measurements.

The assignment and analysis unit is a fresh browser session; repeated keys within sessions are dependent and later typing is not a counted history-depth stratum. Primary outcome is the median trusted-key paint proxy, secondary p95 (only40 samples/block). Compare paired session ratios; report all individual sessions. Forward/reverse order mitigates drift, not host/JIT/GC confounding. The single Unicode pair is a guard, not a broad multilingual effect. Scope is this synthetic corpus on this host/emulation; neither handset nor population speed is identified. No significance, independent-key intervals, formal power or additive component-gain claims. The reversible decision to retain a prototype can use small consistent gains with no fixed universal percentage threshold; mixed outcomes remain explicitly mixed. Do not retry slow valid runs or select only favorable samples.

Positive incremental evidence retains an experimental patch for further work; negative or inconclusive evidence retains the patch and observations without promotion. Selected RC entry still needs native IME/refusal/pending/remote behavior, scratch lifetime/ownership and memory, appropriate broader integration and the unchanged application-latency gate. Release counts/budgets remain unchanged. Round ends after this bounded candidate decision; do not run the full release graph per experiment.
