## Construction and state-machine effect

No cryptographic state machine changes. The suite registry moves two “none” roles into selected state and empties
the deferred map. The check parses TRD §15.1 and rejects any future deferred role whose owner appears in the
selected table.

## Assumptions and guarantee boundaries

The guard assumes the §15.1 Markdown heading/table format and row-number syntax remain stable; it fails loudly if
no selected rows are parsed. It guarantees consistency between this generator's deferral map and the current TRD
register, not completeness of every cryptographic role or correctness of the decisions it imports.

## Evidence and oracle independence

The check reads the authoritative register instead of restating its state, a meaningful improvement over a
well-formed owner string. The commit reports mutation checks for a deferral to selected row 12 and open row 16;
those demonstrations are described in the decision record rather than preserved as a separate test fixture.
Generator and output still share the same suite model.

## Downstream propagation

The repaired roles reach TRD §13.10, the row-1 selection, suite generator, and generated suite JSON. The later
retention check generalizes the same “read the owner” rule to inventory cells.

## Consequences and residual failures

A reviewer no longer sees already-selected roles represented as open. A renamed register/table shape can break
the parser, but the empty selected-set check prevents a silent all-green result. A role omitted from both selected
and deferred data remains a modeling problem this particular cross-document guard cannot discover.

## Falsification attempt and counterevidence

I tested whether this changed any primitive, carrier, KAT, or separation set: the diff changes role metadata and
the register-aware guard only. I also tested the claimed future safety against a stale owner string: because the

evidence shows independent enumeration of all roles, so the broader completeness claim remains bounded.

## Nuance preservation

for rows 13/14 and absence of any secret for row 12. It correctly presents an empty deferred set as the current
state, not proof that no future roles can appear.
