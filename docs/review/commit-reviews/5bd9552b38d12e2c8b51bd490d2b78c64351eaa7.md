# Commit `5bd9552` — Select ASVS 5.0.0 as a floor, and record what it does not cover

## Scope and exact sources

Inspected the full patch and exact objects for `docs/PRD.md`, `docs/TRD.md`,
`docs/selections/row-17-web-security-baseline.md`, `scripts/generate-baseline-vectors.mjs`,
`scripts/check-origin-isolation.mjs`, `scripts/fetch-asvs-index.mjs`,
`scripts/lib/asvs-5.0.0-index.json`, `test/vectors/web-security-baseline.json`, `package.json`, decisions, and
progress at `5bd9552b38d12e2c8b51bd490d2b78c64351eaa7`. Primary source: OWASP ASVS official repository and
v5.0.0 release, https://github.com/OWASP/ASVS and https://github.com/OWASP/ASVS/releases/tag/v5.0.0_release
(retrieved 2026-08-21); the official repository identifies 5.0.0 as the stable May 2025 release and publishes
machine-readable requirements.

## Change seen while moving backward

Returning to `102f3f3` reopens row 17, removes the pinned L2-plus profile, exclusions, pull-ups, deviation, and
five local-first addendum controls, removes the generated profile/count checks, and removes the build-time scan
that claims no remote subresource is present in the built key-holding origin.

## Original-contract trace

This answers OC-079's versioned web-security baseline and supports OC-040/OC-041's pre-ship assurance gates.
The recorded browser-storage deviation carries OC-023's ciphertext-at-rest model instead of pretending ASVS's
browser-storage prohibition is met. The origin addendum is directly load-bearing for OC-039/OC-082 because
same-origin code can use live keys and evidence must test the property actually claimed.

## Construction and state-machine effect

No cryptographic carrier or lifecycle transition changes. The assurance state becomes: ASVS 5.0.0 cumulative
L1+L2 floor; eight named L3 pull-ups; 55 requirements excluded at chapter level with reasons/triggers; one
browser-storage deviation with the encrypted-at-rest compensating control; and five addendum controls for origin,
Trusted Types, service-worker updates, ciphertext-only stores, and offline invariance. Most checks remain future
Stage-1/4 verification; only A1 is marked build-failing now.

## Assumptions and guarantee boundaries

The profile assumes the pinned identifiers/levels accurately represent ASVS 5.0.0 and deliberately does not
vendor requirement prose. Chapter-level inclusion is not per-requirement verification; V6 dispositions in
particular remain future work. The deviation acknowledges that encrypted user content in IndexedDB still violates
V14.3.3 as written. ASVS is a floor, not proof of origin isolation or local-first security, and the addendum's
methods have to become real at the stages named.

## Evidence and oracle independence

The official OWASP repository independently confirms version 5.0.0, release status, and machine-readable form.
The project generator checks chapter coverage, counts, pull-up levels, exclusions, deviations, TRD references,
and existence/planning of addendum checks against its pinned index. It does not verify requirement text during
ordinary checks; `asvs:pin` is deliberately manual. The A1 scanner runs after Vite build, but lines 41–49 only
recognize static `src`/`href`, CSS URLs/imports, ESM imports, dynamic imports, and `importScripts` with literal
HTTP(S) URLs. Other remote-load forms are merely logged as mentions or missed, so its success message is broader
than its oracle.

## Downstream propagation

The profile reaches PRD §7.12, TRD §§10.9, 13.11, 15, and 16, row 17's selection, package build/vector wiring,
the generated baseline artifact, decisions, and progress. Its current claims feed E-19/E-20 and close row 17 in
review 3b's scope.

## Consequences and residual failures

The commit makes exclusions and deviations reviewable instead of hiding them behind an L2 label, and it names
important controls ASVS does not cover. It does not show those controls pass against an implementation. A dynamic
remote fetch/load can pass `check-origin-isolation.mjs`, so an unreviewed party could enter the key origin without
the claimed build gate firing; the exact evidence gap is candidate `f-5bd9552-origin-scan-static-forms`. A direct
Git search of tip application sources found no current third-party app resource, so this is an assurance weakness,
not evidence of an existing remote script.

## Falsification attempt and counterevidence

I tested whether ASVS 5.0.0 was actually a stable, requirement-level source; the official OWASP repository
supports that premise. I tested whether the generated profile equated L2 with complete applicability; it does not,
and explicitly records future per-requirement work. I then tested A1's statement against literal
`fetch("https://third.example/x")`, XHR, URL construction, and DOM APIs such as `setAttribute("src", ...)`:
none appears in the scanner's failing regex set, while the generic URL pass only reports mentions. That surviving
counterexample narrows the affirmative conclusion.

## Nuance preservation

The commit preserves unusually important nuance: the product formally deviates from V14.3.3, L2 is a floor, and
most controls are not yet verified. It overstates only A1's present evidence by printing “no remote subresources”
for a scanner that recognizes a finite set of literal syntaxes.

## Verdict

Supported with qualifications. ASVS 5.0.0 plus explicit exclusions, pull-ups, deviation, and local-first addendum
is a well-considered profile shape. The profile is not verification, and A1 must be narrowed or strengthened before
its claimed build-failing assurance is relied on.

## Findings and unresolved checks

- Candidate `f-5bd9552-origin-scan-static-forms` records the A1 false-negative class.
- Per-requirement applicability, the four future addendum controls, deployment headers, and as-built origin/service
  behavior remain for X-06 and the implementation assurance gate.
