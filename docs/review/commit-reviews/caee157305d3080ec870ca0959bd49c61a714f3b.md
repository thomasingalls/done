## Construction and state-machine effect

Four guarded User Timing marks bracket module evaluation, store open, content-root reconstruction, and store ready.
A serial Playwright suite seeds 20 days × 15 cards plus a 400-line master through the UI, then records first/cold/warm
editable, content-root load, keystroke paint on textarea and CodeMirror, focus-to-editor, and navigation response/
settled. Desktop Chrome and Pixel-7 emulation run separately; the latter uses 4× CPU throttle. Recording writes JSONL
and a manual command formats append-only ledger rows. No storage or product behavior changes beyond inert marks.

## Assumptions and guarantee boundaries

- The fixed 650-record/283.9 kB corpus is a sensitivity fixture, not a claim about a representative user store.
- “Android” means Pixel-7 viewport/user-agent plus 4× host CPU throttle, explicitly not physical low-end hardware.
- Nearest-rank p95 uses 120 isolated keystrokes at 50 ms cadence; other readings are single run observations.
- `goTo` settled and response fit `<100 ms`; animated `step` settled cannot by design, so only its response is
  asserted pending a normative navigation definition.
- One-second post-seed delay plus a reopened-store card count is the durability check; the harness has no direct
  “all updates committed” signal.
