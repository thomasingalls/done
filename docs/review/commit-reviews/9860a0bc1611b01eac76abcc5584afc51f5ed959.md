## Original-contract trace

It answers `OC-025` and `OC-064`: an accepted edit must synchronously reach authenticated persistent journal storage
before handler return, without a nonce counter that can roll back after a crash, and must ultimately meet the low-end
`<1 ms p95` whole-write budget. It also advances the vector requirements in `OC-039`/`OC-082`.

## Construction and state-machine effect

Each journal entry uses XChaCha20-Poly1305 with 24 fresh random bytes. At open, WebCrypto HKDF-SHA-256 derives
`K_journal` from the generation-specific `K_g`, a domain label, and workspace; synchronous writes use raw subkey
bytes only in slot memory. Framing is `"2:" || base64(u32be(gen) || nonce || ciphertext || tag)`. Length-prefixed AAD
binds label, workspace, clear generation, and localStorage slot. Replay reads `gen`, chooses that generation's `K_g`,
derives the subkey, authenticates, then applies the idempotent Yjs update.

## Assumptions and guarantee boundaries

- A secure RNG supplies independent 192-bit nonces; no durable counter/session registry exists to be lost in a kill.
- `K_g` is already generation-specific, so generation is absent from HKDF info and must instead select the correct
  input key during replay.
- The raw journal subkey is the narrow exception to non-extractable runtime keys and is cleared on lock/sign-out.
- The bundled library version has an independent audit in its history, not of the selected 2.3.0 release; the record
  explicitly exposes that gap to review 3a.
- Component AEAD timing is not the TRD whole-write budget; real-device storage measurement remains outstanding.

## Evidence and oracle independence

The generator checks a copied XChaCha published KAT, composition round trips, and tampering of workspace,
generation-AAD, slot, tag, length, and version. Later B-03 mutation work makes the AAD negatives isolated; later
hardware work measures the full localStorage write and finds the 4 kB path over budget. At this SHA, the
“rotated-generation” case proves only AAD binding because every case derives from the same global `KG`; it does not
test the key lookup invariant the selection describes.

## Downstream propagation

Row 1 reserves XChaCha for the synchronous path and AES-GCM for async paths. `dbfd01f` makes row 2 normative. B-03
later replaces the JavaScript provider with audited RustCrypto/WASM after device measurement, strengthens AAD

## Consequences and residual failures

The large random nonce removes crash-persistent state from the safety argument; the IETF draft estimates a `2^-32`
collision chance only after roughly `2^80` messages, far outside a 250 ms journal window. The construction also binds
every trusted clear field. Residuals are evidence/implementation risks: the initial provider audit gap, absent
decision-time whole-write hardware result, and a vector that cannot catch reuse of an old generation key.

## Falsification attempt and counterevidence

I challenged the random-nonce math, counter alternative, and generation omission from HKDF info. The published draft
supports random 192-bit use; page-session counters add exactly the crash state the journal must avoid; and omitting
`gen` from info is sound if a distinct `K_g` is selected first. The strongest counterexample is to that last
condition: an implementation returning gen-1 `K_g` for gen 2 passes every published case because the fixture does the
same. Existing wrong-generation tampering changes AAD, not the derivation input.

## Nuance preservation

The selection faithfully distinguishes primitive latency from whole durable write, recorded audit from current-
version coverage, random fixed fixture nonces from production discipline, and generation AAD from generation key
selection. Later requirements preserve the construction; later evidence changes provider/performance conclusions.

## Verdict

`supported-with-qualifications`: XChaCha, random nonces, KDF, framing, and AAD are coherent and later survive stronger
measurement/review work. The generation-key selection oracle is incomplete and must be fixed before vectors can
justify replay across rotation.
