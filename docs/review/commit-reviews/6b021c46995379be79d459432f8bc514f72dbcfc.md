## Change seen while moving backward

Returning to the parent removes four recorded bundle-size rows and restores the open question of
whether any synchronous WASM seal can fit 43.7 kB of initial-bundle headroom. The parent already shows
that WASM speed could meet the journal budget and that the full libsodium package is too large by an
unpacked comparison; this commit measures gzipped tree-shaken categories, rejects libsodium, and claims
an inlined purpose-built module category fits. It changes no code, package lock, construction, or vector.

## Original-contract trace

This addresses `OC-025`/`OC-064`'s low-end synchronous-journal budget and `OC-050`/`OC-057`'s
review-timing assumption. It also preserves the original §12 initial-JS constraint: a latency fix that
cannot be available before edits or exceeds the bundle gate is not an admissible journal implementation.

## Construction and state-machine effect

None is implemented. The measurement compares a single imported Noble function, standard
`libsodium-wrappers`, an off-the-shelf Rust/WASM narrow-nonce ChaCha20-Poly1305 proxy, and its
base64-inlined form. It reasons that synchronous bundle evaluation needs bytes already present, making
the 24.3 kB inlined proxy the relevant category figure. The remaining choice becomes assurance:
whether compiling an audited RustCrypto XChaCha implementation through Rust/WASM preserves the
“reviewed and widely implemented” criterion.

## Assumptions and guarantee boundaries

- The 43.7 kB headroom is snapshot-specific: 350.0 kB budget minus the recorded 306.3 kB baseline.
- Tree shaking, minification, gzip, dependency version, glue, and import surface determine the sizes.
- The proxy exposes a 12-byte-nonce construction and is explicitly not a candidate for the selected
  24-byte XChaCha format; it estimates category weight only.
- “Fits” means fits the then-current initial-JS headroom. It does not establish synchronous startup,
  correctness, browser support, source-to-binary review, or application integration.
- Emscripten subset cost is a reasoned engineering judgment (“no obvious path”), not an exhaustive
  lower bound on all custom libsodium builds.

## Evidence and oracle independence

The arithmetic is independently reproducible from the prose: the proxy's 24.3 kB leaves 19.4 kB;
libsodium's 149.2 kB is about 3.4 times the 43.7 kB allowance. Noble and libsodium versions are in the
lockfile. The decisive proxy row is not reproducible from the commit: no harness, bundle fixture,
command, result artifact, package name, or version for the off-the-shelf Rust/WASM module is recorded.
The patch contains documentation only.

Later `9b49b74` provides stronger but later evidence by building a real selected XChaCha module and
checking its generated artifact. That supports the category inference in hindsight but was unavailable
as evidence for this commit's decision.

## Downstream propagation

`ffd90e3` repeats the pricing in active documentation. `9b49b74` then constructs the purpose-built

## Consequences and residual failures

The measured libsodium wrapper cannot fit the stated allowance, so rejecting it as the shipping
dependency is well supported. The purpose-built-category result justifies a focused implementation
experiment but not adoption. The missing proxy provenance prevents independent reproduction and could
have mispriced that experiment; the later actual artifact substantially reduces the surviving product
risk without repairing the historical evidence record.

## Falsification attempt and counterevidence

- I recomputed every stated headroom and ratio; rounding is consistent.
- I searched the exact tree and patch for a sizing script, fixture, result file, proxy package identity,
  or build command. None exists; only Noble/libsodium are locked and named.
- I challenged “libsodium cannot ship” as merely an unpacked-size inference. This commit corrects that
  weakness with a 149.2 kB gzipped single-import bundle, still far beyond the allowance.
- I challenged whether the proxy was silently treated as the selected construction. The text repeatedly
  says it is narrow-nonce, non-adoptable, unbuilt, and only category pricing.

## Nuance preservation

The commit preserves that speed, bundle size, primitive width, implementation review, and a working seal
are separate questions. It correctly refuses to equate a small proxy with a candidate, but it fails to
preserve enough provenance to reproduce the measurement itself.

## Verdict

inference is appropriately bounded as a proxy. The unnamed, uncommitted pricing procedure is an evidence
gap, and later actual-module evidence must not be retroactively credited to this decision point.
