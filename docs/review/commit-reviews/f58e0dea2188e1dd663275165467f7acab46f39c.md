## Construction and state-machine effect

Ordinary construction bytes do not change. Each AAD builder now declares its ordered field/value
object through `aadFields()`. In audit mode a subprocess removes one named field from both sealing
and opening AADs, runs all published negatives, and reports which previously failing negative now
authenticates. At least one rescue demonstrates coverage for each declared field. Conversely, each
negative named `aad-only-*` must be rescued by exactly one field. A glob discovers all top-level
vector generators; a generator that emits no audit marker fails, while a genuine no-AAD generator
must explicitly report an empty construction set.

## Assumptions and guarantee boundaries

- The check proves isolation only for fields declared through `aadFields`; generator code remains
  the authority for whether every actual AAD construction and byte was declared.
- A rescued negative establishes that removing that declared field makes that case authenticate. It
  does not independently establish semantic correctness of field values, canonical encoding, key
  derivation, parser behavior, or application integration.
- `refuses()` treats any thrown error as refusal. An unrelated parser/runtime failure remains a
  possible false positive for an ordinary negative, although it cannot produce the specific rescue
  required to claim field isolation unless removing the field also removes that failure.
- Glob discovery prevents silent wholly uninstrumented generators under the naming convention; it
  cannot detect an instrumented generator that reports an incomplete or empty construction set.

## Evidence and oracle independence

The field-elision experiment is materially stronger than structurally diffing vector JSON: a
negative that also changes a derived key will continue failing when only its AAD field is removed
and therefore cannot masquerade as isolated. Producer and checker still share the generator's AAD
builder, field registry, key derivation, and refusal semantics, so this is a mutation check of the
project model rather than an independent implementation.

In a disposable exact-commit archive on 2026-08-21, four of five generator `--check` commands
passed. The full coverage command and journal generator could not execute because the current
workspace has no installed `@noble/ciphers`; Node `v26.7.0` reported that exact missing dependency.
This environment failure neither contradicts the committed output nor reproduces the stated 27-field
run. Static inspection confirms 27 declared fields across five constructions and the build wiring.

## Downstream propagation

Every later top-level vector generator at the pinned tip imports `reportAudit`; generators with AAD
route their named lists through `aadFields`, and no-AAD generators report emptiness. Later protocol
rows therefore inherit the same mutation oracle and its self-declared-construction boundary.

## Consequences and residual failures

The check turns omission of a negative for a declared field and a mislabeled `aad-only-*` negative
into build failures, preventing two concrete evidence regressions. It does not prove that an AAD is
complete for its threat model, that every actual construction is registered, or that the selected
encoding is used by shipping code. Those remain review and integration questions rather than a
reason to reject the check.

## Falsification attempt and counterevidence

- I traced each of the five generator field registries and counted the claimed 27 fields.
- I challenged the original wrong-key-plus-field case: because eliding the field leaves the wrong
  key, it is rescued by none and the converse check rejects an `aad-only-*` label as intended.
- I challenged generator discovery with a wholly uninstrumented file: the missing marker is fatal.
  An instrumented generator can still call `reportAudit()` without declaring a real construction;
  that bounds, but does not falsify, the current five-construction result.
- Four dependency-free exact historical checks passed; the fifth was unavailable rather than
  failing an assertion.

## Nuance preservation

The commit accurately changes the earlier hand-audit limitation into a checked, declared-field
invariant and preserves that it is evidence about vectors, not the implementation. The prose is too
broad only where it implies glob discovery can know an instrumented generator reported all of its
constructions; the code cannot independently establish that completeness.
