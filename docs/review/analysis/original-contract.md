### Blind-pass synthesis

The snapshot distinguishes three layers that must not be collapsed:

1. The normative guarantees and boundaries above are mostly settled, even where no implementation exists.
2. TRD §15 deliberately leaves twenty-one construction, empirical, or cutover selections open; rows 1–3 are the
   immediate Stage 0 blockers, while concrete vectors are a precondition of useful independent review.
3. Evidence gates are part of the contract. A source-controlled threat table, a green test suite that skips
   persistence, an open repository, a valid signature, a state vector, or a within-provider restore each proves less
   than the nearby claim it is liable to be substituted for.

Ambiguities preserved rather than resolved:

- `sequencing.md` §7 warns that any Stage 2 carrier other than export/import is suspicious, while §5.4 and TRD §15
  row 21 explicitly preserve the fidelity archive as the only attribution-preserving alternative. The decision row,
  not the warning shorthand, controls the choice.
- “Local asks for nothing” coexists with optional local device lock: the invariant forbids mandatory account/network
  ceremony, while opt-in factor-gated custody is an expressly accepted strengthening.
- The snapshot calls PRD/TRD current and settled while the progress slice says Stage 0 has not started. These are
  claims about contract maturity and implementation/evidence maturity respectively, not a contradiction.

## Disconfirmed hypotheses and null results

- I tested whether Local/Account could stand in for hosted bytes, replica attachment, session, or entitlement. PRD
  §2.3 explicitly rejects each substitution and enumerates independent axes.
- I tested whether raw Yjs updates could recover actor attribution or filter a device's migration suffix. TRD §4.8
  states that origin never travels and client id is per document instance, rejecting both hypotheses.
- I tested whether valid signatures plus an epoch could distinguish accepted pre-revocation writes from withheld
  writes. TRD §7.5 supplies the hostile-relay counterexample and requires acceptance evidence on every envelope.
- I tested whether a state vector could attest a complete checkpoint. TRD §7.6 rejects it because deletions live in
  the `DeleteSet`; coverage needs `{sv, ds}` or an equivalent receipt.
- I tested whether multiple operator replicas satisfy service continuity. PRD §8.4 and TRD §14.5 reject correlated
  operator custody; the decisive continuity test removes the entire original provider account.
- I tested whether Markdown round-trip could satisfy exact workspace migration. PRD §8 and TRD §9 enumerate the
  deliberate loss of id, author, origin, and createdAt, leaving row 21 genuinely open rather than empirically unknown.

## Affirmative conclusions

- The original snapshot distinguishes normative architecture, unselected construction, implementation state, and
  evidence gates. The matrix preserves those distinctions rather than downgrading fixed negative constraints merely
  because their mechanism remains open.
- Threat actors and failure domains are named with useful precision: raw-profile attacker, same-origin code, hostile
  relay, malicious authorization service, removed credential, offline device, operator/provider loss, and correlated
  recovery-artifact loss are not treated as one “attacker”.
- The plan explicitly anticipates the most consequential evidence substitutions: signature for acceptance, state
  vector for complete checkpoint coverage, operator replica for independent custody, Markdown round-trip for exact
  workspace preservation, green non-persistent property tests for store correctness, and review booking for review
  result.
