## F-03. Row 7's `LP(hex ds)` bound will refuse admission of long-lived workspaces

- **Severity:** high (permanent enrollment failure for large documents; the manifest bytes are durable once a receipt exists)
- **Status:** open (TRD row 7 unchanged)
- **First reported:** review of `e96107b..beed8cf`
- **Where:** `account-protocol/recovery.ts:22-27` (`lp`); `docs/selections/row-7-checkpoint.md:56-61`; `docs/TRD.md:1449`; `src/crdt/promotionAdmission.ts:88`

```ts
// account-protocol/recovery.ts:22
export const lp = (...values: string[]): Uint8Array<ArrayBuffer> => {
  const parts = values.map((value) => {
    if (!/^[\x20-\x7e]*$/.test(value)) throw Error('Non-ASCII protocol field');
    const body = new TextEncoder().encode(value);
    if (body.length > 65535) throw Error('Protocol field too long');
    return new Uint8Array([body.length >>> 8, body.length & 255, ...body]);
```

Row 7 binds the manifest as `... || LP(hex sv) || LP(hex ds) || ...` (`row-7-checkpoint.md:57`, TRD:1449 `done/cp-manifest/v1`). A hex descriptor is therefore capped at 65,534 characters, 32,767 raw bytes. The client refuses before any request (`promotionAdmission.ts:88`: `throw Error('Admission coverage exceeds LP bound')`), and no other path exists. The Yjs delete set only grows over a workspace's life; garbage collection does not shrink it, and nothing flattens history.

Measured with the pinned Yjs 13.6.31, `Y.Text` keystrokes with interleaved backspaces, delete-set-only snapshot as produced by `genesisCoverageParts`:

| Simulated document | `ds` hex characters | Bound |
| --- | --- | --- |
| 1 client, 100k keystrokes | 17,876 | 65,534 |
| 1 client, 300k keystrokes | 56,854 | 65,534 |
| 1 client, 100k random-position edits | 30,712 | 65,534 |
| 3 clients, 300k keystrokes | 70,972 | exceeds |

**Fix:** amend row 7 (and TRD:1449) to bind `SHA-256(sv)` and `SHA-256(ds)` or a 32-bit length prefix, and regenerate the checkpoint vectors, before the first real receipt exists. Measure the owner's actual document before enrollment. Add a test that exercises the refusal (none exists; see F-21).

```resposnse
Intend to fix: yes, before any real Account receipt. Importance: high compatibility/capacity risk. Both manifest and admission LP encodings carry raw hex descriptors, and promotionAdmission refuses above the bound. Hashing descriptors requires amending both signed messages, with explicit versioning and regenerated cross-implementation vectors; changing only the manifest is insufficient. Permanent failure is overstated: a fresh semantic import/rebase can reduce history, and delete-set ranges can coalesce, so size is not strictly monotone. It is nevertheless an unjustified enrollment ceiling. The reported measurements were not independently rerun here.
```
