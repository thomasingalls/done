## Findings that affect synthesis

1. **The receive/admission boundary needs new integration work.** Every candidate promoted a remote
   insertion into the editor/canonical document and a deletion into the canonical document before content commit. Codex displayed
   `RL` and reopened empty in the short dependency case. Contract-pass and encrypted-store recovered
   that short case, but all three reopened empty after displaying **17,409 characters** in the larger
   case: 17 KiB of remote text followed by a local `L`. Incidental journal coverage of small remote
   updates is insufficient. The failure is observed through the actual application/editor bridge and
   a renderer crash, with no remote redelivery on reopen.
2. **Private pending input is not implemented correctly in any candidate.** The first refused edit and
   the following edit leaked into the editor, ordinary export and undo history. Codex's transport
   document did stay private in this schedule; its editor/export/undo leakage still fails the contract.
3. **Contract-pass has useful trim/load behavior, with an additional repair required.** It passes
   independent-writer replay, late-reservation preservation and whole-trim refusal on corrupt input.
   The three guard-removal controls below discriminate those behaviors. However, all three candidates
   deleted an observed row whose bytes changed between snapshot commit and deletion. Exact sequence
   identity alone does not implement the corrected identity-and-bytes comparison.
4. **Custody and lifecycle obligations remain substantial.** None held a shared writer permit during
   the freeze probe. All allowed persistent genesis without a factor, and every complete copied test
   profile reopened known content without a factor. These observations concern the pinned implementations
   and this Chromium configuration; they do not certify the eventual supported-platform threat model.
5. **Clear and startup results support selecting individual ideas.** Codex and contract-pass preserve
   WAL when content deletion refuses, but leave it behind after successful clear. Encrypted-store clears
   it on success but loses it before a refused content deletion. Contract-pass and encrypted-store keep
   seeded legacy content visible on default startup; Codex instead opens an empty store.

These results support a deliberate synthesis around a new admission/lifetime coordinator, with
contract-pass's authenticated disk-union trim and fail-closed load as component donors after repair.
They do not support merging any candidate wholesale or treating component pass counts as correctness.

## Boundaries and remaining work

Receive injection is at the production provider-document seam, before a future encrypted wire verifier.
The death test kills a renderer, not the OS. The freeze test observes held shared locks; it does not run
an absent exclusive generation/retirement worker. C13 uses a complete copied profile on the same host
under Playwright's mock-keychain settings; valid-factor, wrong-factor, future-receiver and supported
browser/authenticator controls are absent. Clear uses a synthetic authorized slot inventory and does
not prove Account authentication, ClearIntent resumption, terminal markers or shared-key isolation.

The next implementation unit is the admission/lifetime coordinator, followed by its wiring into editor,
receive, custody and clear paths, with shared scenarios added as those APIs become available. Concurrent
transition/interruption cases, complete carrier references, mandatory-factor controls, supported import
and the seeded legacy cutover matrix remain owed. **No debt or release gate is paid by this record.**
